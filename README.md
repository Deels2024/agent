# Агент покупок

Полный full-stack проект сервиса, который помогает покупателю найти товар по названию, фотографии или штрих-коду, сравнить предложения маркетплейсов и небольших магазинов, увидеть итоговую цену и выбрать надёжного продавца.

Рабочая версия: https://buyer-agent-prototype.deels.chatgpt.site

## Что входит в репозиторий

- клиентский веб-сервис с пятью разделами: поиск, цены, покупки, помощь и профиль;
- рабочая страница поиска с сортировкой до 10 предложений;
- распознавание товара по фотографии через OpenAI Responses API;
- поиск по названию и штрих-коду;
- адаптеры Wildberries, Ozon и Яндекс Маркета;
- предложения небольших продавцов и сценарий безопасной сделки;
- прозрачная карточка предложения: товар, доставка, итог к оплате, гарантия, возврат и рейтинг;
- история поисков и предложений в Cloudflare D1;
- центр интеграций и веб-интерфейс контроля backend;
- полный кликабельный дизайн из 40 экранов покупателя, продавца и администратора;
- адаптивная вёрстка для компьютера, планшета и телефона;
- серверные API, миграции базы, расширенные тесты, CI и конфигурация production-сборки.

Пример запроса:

```bash
curl -X POST http://localhost:3000/api/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"Apple AirPods Pro 2 USB-C","mode":"text","limit":10}'
```

Без ключей маркетплейсов поиск запускается в честном демонстрационном режиме. Демо-предложения всегда помечаются и не выдаются за актуальные цены. Страница `/api/health` показывает фактическую готовность распознавания фото и постоянной истории, а не обещает неподключённые возможности.

## Технологии

- TypeScript, React 19 и Next.js 16;
- Vinext и Vite;
- Cloudflare Workers и D1;
- Drizzle ORM;
- OpenAI Responses API для поиска по фотографии;

## Быстрый запуск

Требуется Node.js `22.13` или новее. В Linux/CI рекомендуется защищённая установка проекта:

```bash
git clone https://github.com/Deels2024/agent.git
cd agent
npm ci
cp .env.example .env.local
npm run dev
```

В Linux можно заменить `npm ci` на `npm run install:ci`: скрипт проверяет lock-файл, повторяет временно оборванные загрузки и не выполняет lifecycle-скрипты сторонних пакетов.

После запуска откройте адрес, который покажет Vite. Поиск по названию доступен и без внешних ключей.

Production-сборка:

```bash
npm run build
npm run start
```

`npm run start` удобен для локальной проверки интерфейса, но Node-адаптер Vinext не создаёт Cloudflare D1. Поэтому для серверного Docker-запуска используется отдельная команда `npm run start:docker`: она запускает собранный Worker в workerd и хранит D1 в постоянном Docker volume.

### Развёртывание на собственном сервере

```bash
git clone https://github.com/Deels2024/agent.git
cd agent
cp .env.example .env
chmod 600 .env
docker compose -f docker-compose.server.yml up -d --build --wait
curl --fail http://127.0.0.1:8788/api/health
```

Контейнер считается здоровым только когда доступна постоянная база. Данные D1 сохраняются в volume `worker_state` и не теряются при пересборке контейнера. Файл `.env` остаётся только на сервере и не должен попадать в Git.

В Docker по умолчанию включён `AUTH_MODE=standalone`: пользователь регистрируется по email и паролю на странице `/login`, пароль хранится как PBKDF2-хеш, а сеанс — в постоянной D1-базе с HttpOnly cookie. Для версии Sites используется `AUTH_MODE=chatgpt` или значение по умолчанию без переменной — тогда вход подтверждает платформа ChatGPT. Публичный сервер всё равно должен работать через HTTPS reverse proxy.

Проверки:

```bash
npm run lint
npm test
npm audit --omit=dev --audit-level=high
```

Эти же проверки автоматически выполняются GitHub Actions при каждом push и pull request в `main`. Dependabot раз в неделю предлагает безопасные обновления npm-зависимостей.

### Ограничение официальных API

Подключённые сейчас официальные API предназначены для кабинетов продавцов и показывают товары соответствующих продавцов. Глобальный поиск по всему публичному каталогу Wildberries, Ozon и Яндекс Маркета требует отдельных партнёрских договорённостей с площадками. Неавторизованный scraping в проект намеренно не добавлен.

## База данных

В D1 сохраняются:

- поисковые запросы;
- найденные предложения и цены;
- результаты распознавания фотографий;
- технические события интеграций.
- профили и роли пользователей;
- магазины, KYC-проверки, подключения, товары и остатки;
- заказы, платёжные намерения, доставки, подписки и споры;
- ценовые правила и очередь уведомлений;
- события риска, лимиты запросов и неизменяемый аудит действий.

Схема находится в `db/schema.ts`, готовая миграция — в `drizzle/`.

После изменения схемы:

```bash
npm run db:generate
```

При первом обращении backend также безопасно создаёт отсутствующие таблицы через `db/ensure.ts`.

## 15 модулей коммерческого запуска

Проект содержит единый рабочий контур для входа, ролей, кабинета продавца, зашифрованных ключей, заказов, платёжных намерений, KYC, доставки, уведомлений, Plus, ценовых правил, антифрода, мониторинга, документов и публичного запуска. Фактическое состояние каждого модуля показывает `/platform` и API `/api/platform/status`.

Внешние операции не имитируются. Без договора и ключей платёжный модуль остаётся в `sandbox`, KYC и доставка показываются как требующие партнёра, а демонстрационные цены не запускают уведомления и не создают списания. Для боевого запуска нужно выбрать официальных партнёров, заполнить защищённые переменные сервера, проверить юридические тексты и только затем включить публичный доступ.

### Безопасность

- права проверяются в серверных маршрутах, а администраторы задаются через `ADMIN_EMAILS`;
- страница `/admin` также проверяет `ADMIN_EMAILS` на сервере до загрузки любых административных данных;
- собственный сервер использует защищённые email/password-сессии, а Sites завершает платформенный сеанс ChatGPT;
- ключи кабинетов продавцов шифруются AES-256-GCM ключом `CREDENTIAL_ENCRYPTION_KEY` и никогда не возвращаются API;
- платёжные запросы используют идемпотентность, а входящие события платежей и доставки — HMAC-подпись;
- критичные операции ограничены по частоте, сетевые признаки хешируются, действия записываются в аудит;
- `PAYMENT_PROVIDER=sandbox` никогда не списывает деньги.
